## A. Pre-run gate — answer every question before an experiment is approved

**Applicability column (R12, rewritten by R2-K):** Applicability classes are **`mechanism-only diagnostic`** (no causal contrast, no remedy), **`causal diagnostic`** (≥2 arms with a contrast claim), **`remedy validation`**, **`baseline`**. A3/A4/A6 apply to `causal diagnostic` and `remedy validation`; for `mechanism-only diagnostic` they are N/A with the no-contrast claim recorded. Every class must record an explicit no-remedy/no-production-change boundary and a rule that evidence implying a remedy triggers STOP and a new proposal. An item may be **N/A** (a) for an experiment class it does not govern, or (b) for a **named sub-check** that is structurally impossible at the current stage/design (e.g. A11 "model rank" on a single-arm run, A16 as a demoted gate reference, A13's "one further iteration authoriser" on a no-remedy diagnostic) — in both cases only with written justification plus independent reviewer concurrence at `approval` stage (DEFERRED at `design` stage), never as a silent NO. **A whole item that applies to the class cannot be made N/A by citing a sub-check exception.** "Baseline" remains the full-flow D-007 verification class; a baseline *arm* nested in another class is recorded as an arm, not as the `baseline` class.

**Stage column (R2-A):** Each item declares the stage at which its PASS condition is answerable — `design` (pre-approval planning), `execution` (at run time), `post-run` (after the run). A checklist completed at `design` stage records execution/post-run evidence as **DEFERRED**, naming the artifact and the owner who will confirm it. `DEFERRED` is neither PASS nor NO and does not trigger the GATE RULE. The GATE RULE applies only to conditions answerable at the current stage.

**Disposition legend:** **PASS** = item satisfied as defined at the stated stage; **FAIL** = required condition broken (gating NO); **PARTIAL** = substance present with a recorded gap that the independent reviewer must accept or escalate; **UNKNOWN** = evidence unavailable at the current stage (not a PASS; resolve or record as a named limitation — an UNKNOWN required *capability* is STOP for the dependent item, R2-J); **N/A** = item/sub-check does not apply to this class, with justification and concurrence; **DEFERRED** = answerable only at a later stage, naming the confirming artifact and owner — neither PASS nor NO, not a silent PASS, and not a STOP trigger. Per-item definitions are in **§ A.1**.

**GATE RULE (stage-aware, class-aware; NO vs N/A vs DEFERRED explicit — R3 + R12 + R2-A/R2-K).** **STOP applies only to an item that (i) applies to this experiment class and (ii) is answerable at the current stage and (iii) is FAIL/NO, or carries an UNKNOWN on a required capability (R2-J).** **DEFERRED is neither PASS nor NO and does not trigger STOP**; it is used only for a condition whose PASS is answerable at a later stage, and must name the artifact and the owner who will confirm it (A11 preflight, A12(b) post-run confirmation, A15 sign-off/concurrence, A10 evaluated pins, A16 rollback evidence). DEFERRED is not a silent PASS: the named confirmation must be recorded in §B at the declared `execution`/`post-run`/`approval` stage before the run proceeds past that stage. **N/A is not NO and not a silent PASS:** it is permitted where the applicability column excludes the class (including the four classes of R2-K and the `mechanism-only diagnostic` N/A for A3/A4/A6), or for a **named sub-check** that is structurally impossible at this stage (A11 "model rank" on single-arm runs; A13 "one further iteration authoriser" on a no-remedy diagnostic; A4 decision/approval IDs where the delta is an instrumentation factor; A16 as a demoted reference) — with written justification and independent reviewer concurrence recorded in the approval evidence (concurrence DEFERRED at `design`, required at `approval`). An applicable whole item cannot be made N/A by a sub-check exception. There is **no blanket STOP for mechanism-only diagnostics**: with the no-contrast claim and no-remedy boundary recorded, A3/A4/A6 are N/A under R2-K/R2-F. Conversely, any **causal or remedy claim** with A3 FAIL/NO (including a mislabelled "instrumentation identity" arm cited as the control) is STOP regardless of other labels. **PARTIAL** is not PASS: the independent reviewer must either accept the recorded gap as a bounded deviation or escalate it to NO. **UNKNOWN** is not PASS: resolve before approval or accept as a named limitation with reviewer concurrence; an UNKNOWN required measurement capability is STOP for the dependent item (A11 probe, A17). A13 no-remedy scope is not a fabricated FAIL. A9/A15 share one named reviewer (R2-E/R2-L). A8 fixes the bar but never assigns PASS — **D-007 report-level human review remains binding**.

## D. Exclusions (what this checklist must never do)

- Never install, import or execute the upstream skill, its scripts, `uv/pip` commands, network fetches
  or CSV outputs. `experimental-design` remains `RECOMMENDED`, not installed and not active.
- Never modify `AGENTS.md`, approval policy, runner, KB records or any protected artifact.
- Never run EDA or start a physical-design experiment by itself.
- Never define or auto-assign PASS; D-007 report-level human review remains binding.
- Never change catalog statuses from `RECOMMENDED` without explicit user adoption authorization.
- Never treat N/A as a silent PASS or as NO; N/A requires class exclusion, justification and concurrence.
- Never **force a DEFERRED condition to NO/FAIL** or treat it as a silent PASS; DEFERRED names the artifact and owner and does not trigger STOP at the stage where it is deferred.
- Never demand an `execution` or `post-run` artifact from a `design`-stage proposal (A11 preflight, A12(b) confirmation) — record it DEFERRED instead.
- Never impose a remedy-validation bar on a diagnostic, nor cite instrumentation-neutrality (or an arm merely labelled "instrumentation identity") as a control — only a modification-digest identity qualifies.
- Never manufacture a cost cap or "one further iteration" authoriser for a no-remedy diagnostic; use the bounded-resource statement and the N/A sub-check.
- Never infer a remedy from diagnostic evidence: doing so triggers **STOP and a new proposal** (R2-K).
- Never count sub-units, pins, markers or remedy-family levels as independent replicates.
- Never activate this checklist as a gate before the confirmatory shadow/observational pilot and explicit adoption; **R2 is DRAFT / INACTIVE**.

## E. Usage

Use this checklist when preparing an FDE experiment proposal, before the approval gate. Record the
completed **A1–A17** answers (A16 as the demoted reference line; A17 as the mandatory measurement-capability item) in the experiment's approval evidence, with
the applicability class (one of the four R2-K classes), the stage of each item, every N/A justification and concurrence, and every DEFERRED artifact/owner/confirmation stage. A15's independent reviewer signs off on **A1–A17** (A16 is a reference line)
before approval at `approval` stage; in a shadow/observational assessment with no approval gate, A15 is
**DEFERRED-SHADOW** and a missing sign-off is not NO. One named reviewer may satisfy A9 and A15 (recorded once in §B). UNKNOWN on a required measurement capability stops the dependent item (A11/A17). Status remains **DRAFT / INACTIVE methodology reference** until the user authorizes
adoption of PS-001 **and** the confirmatory shadow/observational pilot is completed; using it for planning does not
install or activate the external skill and does not turn this checklist into an active gate.
