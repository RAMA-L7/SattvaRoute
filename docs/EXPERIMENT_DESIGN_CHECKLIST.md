## A. Pre-run gate — answer every question before an experiment is approved

**Applicability column (R12):** `diagnostic` / `remedy validation` / `baseline`. An item may be **N/A** (a) for an experiment class it does not govern, or (b) for a named sub-check that is structurally impossible pre-run in this design (e.g. A11 "model rank" on a single-arm run, A16 as a demoted gate reference) — in both cases only with written justification plus independent reviewer concurrence, never as a silent NO. A whole item that applies to the class cannot be made N/A by citing a sub-check exception.

**Disposition legend:** **PASS** = item satisfied as defined; **FAIL** = required condition broken (gating NO); **PARTIAL** = substance present with a recorded gap that the independent reviewer must accept or escalate; **UNKNOWN** = evidence unavailable pre-run (not a PASS; resolve or record as a named limitation); **N/A** = item does not apply to this class, with justification and concurrence. Per-item definitions are in **§ A.1**.

**A16 disposition — choice and justification.** Per the review's instruction ("If judged already covered by FDE-002, demote to a reference line rather than a new gate"), I judged A16 **already covered** and demoted it. Evidence read (read-only): `scripts/sattva_approval.py` (FDE-002) documents that `apply_patch()` "writes before/after + rollback evidence," creates a backup, and on post-apply hash mismatch restores the original with `phase="rolled_back"`; D-014 (DECISIONS.md) records that the ORFS execution mirror is git-cleaned at every run start; A12 now covers immutable artifacts and baseline-ODB hashes. A16 therefore adds no new pre-run gate condition — it is retained as a reference line with an explicit evidence-attachment expectation (section B), and its five dispositions are still defined in § A.1 for traceability.

**GATE RULE (class-aware; NO vs N/A explicit — R3 + R12).** If an item that **applies to this experiment class** is **FAIL / NO**, **STOP** — do not launch a run or amend the remedy without a new decision and approval gate. **N/A is not NO and not a silent PASS:** it is permitted where the applicability column excludes the class, or for a named sub-check that is structurally impossible pre-run, with written justification and independent reviewer concurrence recorded in the approval evidence; an applicable whole item cannot be made N/A by a sub-check exception. In particular, a **mechanism-only diagnostic that asserts no causal contrast** may mark A3 (and, where inapplicable, A4/A6/A10) as N/A under R3/R12 — there is **no blanket STOP for such diagnostics**. Conversely, any causal or remedy claim with A3 FAIL/NO is STOP regardless of other labels. **PARTIAL** is not PASS: the independent reviewer must either accept the recorded gap as a bounded deviation or escalate it to NO. **UNKNOWN** is not PASS: it must be resolved before approval or explicitly accepted as a named limitation with reviewer concurrence. A8 fixes the bar but never assigns PASS — **D-007 report-level human review remains binding**.

## C. Anti-patterns mapped to SattvaRoute history

| Upstream structural error | SattvaRoute occurrence | Required handling |
|---|---|---|
| Pseudoreplication | counting 9 FlexPA candidates or 107 marker records as independent evidence | count independent runs only; N = run IDs (A2) |
| No proper control | early remedy attempts without a concurrent identity (no-op) arm | identity arm required for causal/remedy claims; instrumentation-neutrality is not a control; diagnostic N/A only with justification + concurrence (A3) |
| Confounding by nuisance | binary/config/ODB changes between arms | pin and hash all inputs; toolchain manifest (A4/A5/A14) |
