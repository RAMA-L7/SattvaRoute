# Naming and identity rationale

## Name

**SattvaRoute**

## Intended meaning

> **Clear engineering reasoning with a controlled path toward recovery.**

- **Sattva** — used here as a shorthand for *clarity, balance, integrity, and disciplined reasoning*. It expresses the project's preference for evidence over assumption and for honest statuses over optimistic labels.
- **Route** — the physical-implementation path (placement, CTS, routing) and, more generally, a controlled path from a failed state toward a verified recovery attempt.

This is the project's stated brand rationale, not a linguistic or historical claim about either word. No external etymology is asserted.

## What the name commits the project to

- Evidence before conclusions.
- Narrow, reviewable corrections.
- Human control over change.
- Isolation of recovery attempts.
- Independent verification.
- Honest outcomes (`PASS`/`FAIL`/`BLOCKED`/`UNKNOWN`/`INCONCLUSIVE`/`NOT RUN`/`NOT EVALUATED`).

If a future version of the project violates these principles, the name no longer describes it.

## Visual identity guidance (lightweight)

No logo or dedicated visual asset currently exists in this repository. Documentation should therefore be consistent in *style*, not branding:

- **Tone:** senior engineer to senior engineer; precise, restrained, no marketing language.
- **Terminology:** use `docs/reference/GLOSSARY.md` exactly; no synonyms that blur proposal vs approval vs verification.
- **Diagrams:** Mermaid, consistent node names matching the glossary, implemented elements solid, planned elements labeled and dashed. See `docs/diagrams/`.
- **Color:** not required; avoid implying status with color alone. Status is always written as text.
- **Typography:** plain Markdown headings and tables; no decorative assets, no fonts added to the repository.
- **Assets:** do not replace or redesign any existing branding without owner approval.
